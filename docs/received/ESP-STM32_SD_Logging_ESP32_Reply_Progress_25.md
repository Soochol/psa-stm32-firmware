## 1. 검증 — 통과했습니다

2분 로테이션 빌드로 바꿔주셔서 5분 안에 끝났습니다. 감사합니다.

### 1.1 재부팅이 없었음을 먼저 확정합니다

이 검증의 전제입니다. 전원을 껐다 켜면 부팅 스캔이 등재해버려 수정 덕인지
구분되지 않습니다(보고 #24 §3에서 저희가 밝힌 그 문제).

| 시각 | 장치 보고 |
|---|---|
| 검증 시작 | `boot=95 lastSeq=1179 tick=129746 file=0` |
| 검증 종료 | `boot=95 lastSeq=3001 tick=311828 file=2` |

**bootId가 95로 동일**하고 tick이 129 s → 311 s로 이어집니다. ESP32 시리얼에
**리셋 흔적(`rst:0x`·`ESP-ROM`)이 0건**입니다. 같은 세션이 끊김 없이 계속됐습니다.

### 1.2 그 세션 안에서 file 0이 목록에 나타났습니다

```
device holds 49 file(s)
  boot=95 seq 0..1200 (1201 records) file=0     ← 현재 세션의 파일
```

**1,201 레코드 = 120.1초**로, 설정하신 2분 로테이션과 정확히 일치합니다.
파일이 닫히자마자 목록에 올라왔습니다.

이전 동작이라면 `boot=95`는 **하나도** 보이지 않아야 합니다. 저희가 보고 #22 §2에서
관측한 것이 정확히 그 상태였습니다(현재 bootId의 파일이 목록에 0개).

### 1.3 연속 로테이션에서도 성립합니다

몇 분 더 두고 다시 조회했습니다.

```
device holds 51 file(s)
  boot=95 seq    0..1200 (1201 records) file=0
  boot=95 seq 1201..2401 (1201 records) file=1
  boot=95 seq 2402..3602 (1201 records) file=2
```

**세 파일 모두 1,201 레코드로 정확히 같고, 전부 재부팅 없이 등재됐습니다.**
한 번 우연히 동작한 것이 아니라 로테이션마다 반복됩니다.

### 1.4 ⚠️ `indexed=N` 대조는 저희가 할 수 없습니다

보고 #24 §1.4의 로그입니다.

```
[I/SD_LOG]closed 00000032_0001.psa size=1966592 indexed=22
```

**이것은 STM32 자체 로그라 ESP32 시리얼에는 오지 않습니다.** 저희가 보는 것은
`0x45` 응답뿐입니다. 저희 쪽 total은 위 조회 시점 기준 **49 → 51**이었습니다.
그쪽 RTT에 남아 있으면 대조해 주십시오.

## 2. 등재된 파일에서 데이터가 실제로 나옵니다

목록에 나타나는 것과 읽히는 것은 다른 문제이므로 함께 확인했습니다.

```
--boot 95 --start-seq 0 --limit 200
→ 200 records, 3 batches
```

| 항목 | 결과 |
|---|---|
| seq 범위 | 0~199 |
| 기대 / 기록 | 200 / **200** |
| 수집률 | **100.00%** |
| 갭 · 무효 · CRC 실패 · 불변식 위반 | **0 / 0 / 0 / 0** |

**세션이 진행 중인 상태에서, 방금 닫힌 파일을 읽었습니다.** 이것이 저희가
보고 #22 §2.3에서 "현장에서 성립하지 않는다"고 적은 시나리오입니다 —
이제 성립합니다.

## 3. 부수 소득 — `firstSeq` 연속성을 동적으로 재확인했습니다

보고 #17 §2.2에서 카드를 뽑아 **정적으로** 확인하신 항목입니다. 이번에는
**동작 중에** 경계 3곳이 만들어지는 것을 그대로 봤습니다.

| 경계 | 앞 파일 마지막 | 뒤 파일 첫 | 연속 |
|---|---|---|---|
| file 0 → 1 | 1200 | **1201** | ✅ |
| file 1 → 2 | 2401 | **2402** | ✅ |

**세 파일 모두 정확히 1,201 레코드**이고 어긋남이 없습니다. `v_log_idx_add()`가
카운터가 아니라 헤더를 다시 읽고 파일 크기로 계산한다는 §1.3 설명과 일관됩니다.

## 4. 요청 — 로테이션 주기를 되돌려 주십시오

검증이 끝났으므로 원래 값으로 부탁드립니다.

```c
// sd.c:390
#define SD_LOG_ROTATE_ITV   (60UL * 60UL * 1000UL)   // 1 hour
```

2분 주기로 두면 파일 수가 시간당 30개씩 늘고, `0x45` 목록도 그만큼 길어집니다.
현재 이미 51개입니다.

### STM32 무응답 — 다시 한 번 관측했습니다

`boot=56` 세션 이후 확인하러 갔을 때 `backfill failed: STM32 not ready`로
거부됐습니다. 그 시점 STAT도 오지 않았습니다. 이번에도 RTT가 없어 그쪽
자료는 없습니다.

다만 저희가 확인한 사이 bootId가 **56 → 95**로 올라 있었습니다. 그 사이
그쪽에서 여러 번 적재하신 것으로 보이므로, **저희가 본 무응답이 적재 중
상태였을 가능성**이 있습니다. 그렇다면 결함이 아닙니다.
