## 1. 문제 진단에 동의합니다

> 상한은 RAM 인덱스의 한계이지 파일시스템의 한계가 아닙니다.

정확합니다. 그리고 **가장 필요할 때 실패한다**는 지적이 이 제안의 핵심입니다 —
카드를 비우려는 상황이 곧 초과분이 생기는 조건입니다.

`f_mkfs`를 안 쓰겠다는 판단도 맞습니다. 로그 파일만 지우면 목적이 달성되고
FAT·클러스터를 재작성하지 않으므로 **실패해도 카드가 남습니다.**

§4의 "명령은 한 가지만 한다"도 동의합니다.

> 되돌릴 수 없는 명령일수록 하는 일이 하나여야 실패를 해석할 수 있습니다.

`0x56` stop → `0x58` → `0x56` start 순서를 호출자에게 두는 것이 맞습니다.

## 2. 🔴 한 호출로 다 지우면 워치독에 걸립니다

### 2.1 계산

`f_unlink` 하나는 디렉터리 항목 쓰기 + FAT 체인 해제입니다. 2.88 MB 파일이면
32 KB 클러스터 기준 약 90개 항목을 훑습니다.

저희 실측에서 SD 쓰기는 **5~50 ms** 대역입니다. `f_unlink`도 같은 급으로 보면:

| `f_unlink` 가정 | 150개 소요 |
|---|---|
| 10 ms | 1.5 s |
| **20 ms** | **3.0 s** ⚠️ |
| 50 ms | 7.5 s ⚠️ |

**IWDG 타임아웃은 2.0초**이고, 메인 루프는 한 바퀴에 한 번 갱신합니다
(`main.c:1891`). 삭제 루프가 그 안에서 돌면 **갱신이 멈춥니다.**

그리고 저희 SD 대기 훅은 **의도적으로 IWDG를 갱신하지 않습니다** — 카드가
물렸을 때 자세 제어가 멈춘 채로 계속 도는 것을 막기 위해서입니다.

### 2.2 그래서 삭제 도중 리셋됩니다

**가장 나쁜 형태입니다.** 지우다 만 상태로 재부팅하고, PC는 결과를 못 받고,
다시 걸면 또 중간에 리셋됩니다. **파일이 많을수록 확실히 실패**하므로 §1.1의
문제가 형태만 바꿔 남습니다.

### 2.3 제안 — 시간 예산 안에서 지우고 나머지를 알립니다

한 호출에서 **약 500 ms** 동안만 지우고 반환합니다.

| 결과 | 뜻 |
|---|---|
| **0** | 완료 — 로그 디렉터리가 비었습니다 |
| **6** | **부분 삭제 — 남았습니다. 다시 부르십시오** |
| 2 · 3 · 4 · 5 | 제안하신 그대로 |

**삭제 개수(Q74)는 이 호출에서 지운 수**입니다. PC는 결과가 0이 될 때까지
반복하고, 누적하면 총계가 나옵니다.

```
0x58 → 결과 6, 개수 24   ← 계속
0x58 → 결과 6, 개수 26
0x58 → 결과 0, 개수 11   ← 완료. 총 61개
```

**개수를 실어달라는 요청이 여기서 두 몫을 합니다** — 검증용이면서 진행 표시가
됩니다.

### 왜 개수가 아니라 시간으로 끊나

카드마다 `f_unlink` 소요가 다릅니다. **"20개씩"으로 끊으면 느린 카드에서 다시
워치독에 닿습니다.** 시간으로 끊으면 카드 속도와 무관하게 상한이 지켜집니다.

### 2.4 디렉터리를 순회하며 지우지 않겠습니다

`f_readdir` 진행 중에 `f_unlink`를 부르면 디렉터리 커서 상태가 어떻게 되는지
FatFs가 보장하지 않습니다. **이름을 먼저 모으고 디렉터리를 닫은 뒤 지웁니다.**

```
반복 {
    f_opendir → .psa 이름을 최대 16개 수집 → f_closedir
    수집한 것들을 f_unlink
} 시간 예산이 남아 있고 수집분이 있는 동안
```

지워진 항목은 다음 `f_opendir`에서 건너뛰므로 반복이 수렴합니다. 이름 버퍼는
16 × 18 B ≈ 288 B로 스택에서 감당됩니다.

## 3. 매직 값

`0xDEADBEEF` 그대로 쓰겠습니다. **값보다 있다는 사실이 중요**하고, 흔한 상수라
로그에서 눈에 띄는 것도 이 용도에는 장점입니다.

프레이밍 오류가 우연히 이 명령이 되는 것을 막는다는 근거에 동의합니다 —
`0x58`은 CTRL 대역이라 파서가 카테고리로 받아들이므로, **페이로드가 비어 있으면
잡음이 그대로 실행됩니다.**

## 4. 결과 코드 공유 (Q73)

이견 없습니다. **같은 성격의 거부에 다른 번호를 붙이면 양쪽 구현이 갈린다**는
근거가 맞습니다.

다만 §2.3의 **결과 6**이 추가됩니다. `ctrlLogDelete`에는 없는 값이지만 성격이
달라 겹치지 않습니다 — 그쪽은 단건이라 "부분"이 없습니다.
