# 통합 상태 노트 #15 — 단일 담당 전환 · Q43 종결

> **성격**: 팀 간 회신이 아닙니다. **ESP32·STM32 두 리포를 한 담당이 맡게 되어**,
> 이후로는 왕복 문서 대신 통합 노트로 기록합니다.
> **전환 시점**: 2026-08-12
> **ESP32 펌웨어**: `a691ed3` / **STM32 펌웨어**: `9508917`
> **이 노트가 바꾸는 것**: 냉각 기준값 **96초 → 약 50초** (§1)

---

## 0. 담당 전환과 그 대가

지금까지 두 리포는 별도 담당이 맡아 문서로 정보를 주고받았습니다. 이제 한 담당이
양쪽을 봅니다. 얻는 것과 잃는 것이 분명해 먼저 적어 둡니다.

**얻는 것** — 지금까지 "상대 코드를 볼 수 없어 확정할 수 없다"로 남던 항목을
직접 대조할 수 있습니다. §3이 그 첫 결과입니다.

**잃는 것 — 이쪽이 더 중요합니다.** 이 교환에서 **상호 검토가 실제로 오류를
잡았습니다.**

| 잡힌 쪽 | 항목 |
|---|---|
| ESP32 | `0x81`을 상태 조회로 쓰려 한 것 (STM32가 지적) |
| ESP32 | `0x12` 값 잔존 — 힐링 80이 남는 경로 (STM32가 지적) |
| ESP32 | 여유값 10 °C — 낙차 8 전환을 놓침 (STM32가 지적) |
| ESP32 | 냉각 기울기와 피팅 `k` 불일치 (STM32가 지적 → §1) |
| STM32 | 히터를 "STM32 관리"로 분류 — 실은 ESP32 GPIO (ESP32가 지적) |
| STM32 | §16.3-3에 철회된 ⑭ 잔존 (ESP32가 지적) |

**단일 담당이 되면 이 교차 검증이 사라집니다.** 보완책으로 다음을 지킵니다.

1. 어느 쪽 주장이든 **문서 인용이 아니라 코드·캡처로 검증**한 뒤 기록합니다.
2. 두 리포의 판단 근거는 ESP32 리포의
   `docs/verification/2026-08-12-stm32-e2e/findings.md` **한 곳**에 모읍니다.
3. 이미 발행된 문서는 **수정하지 않습니다.** 정정은 이 노트처럼 뒤에 덧붙입니다
   (v1.6 변경 이력 표를 사후 수정하려다 되돌린 사례와 같은 이유).

## 1. 🔴 Q43 종결 — 냉각 기준값을 정정합니다

`STM32_Reply_Progress_13` §3이 제기한 불일치가 **맞았습니다.**
그리고 그 결과 `STM32_Reply_Progress_14` §1이 고정한 **기준값 96초는 과대추정**입니다.

### 1.1 무엇이 틀렸나

ESP32 `capture_03`(240초, 2,402표본)에 뉴턴 냉각 단일 지수를 맞춰 `k = 0.00400`을
얻고, 그 `k`를 잔열 구간에 적용해 96초를 냈습니다. **냉각이 단일 지수가 아닙니다.**

| 구간 | 중심 온도 | 실측 기울기 | `k=0.004` 예측 | **국소 `k`** |
|---|---|---|---|---|
| 28–48 s | 74.3 °C | 0.374 °C/s | 0.185 | **0.00806** |
| 48–68 s | 67.7 °C | 0.266 | 0.159 | 0.00670 |
| 88–108 s | 61.5 °C | 0.156 | 0.134 | 0.00463 |
| 168–188 s | 52.4 °C | 0.085 | 0.098 | 0.00350 |
| 248–268 s | 46.4 °C | 0.040 | 0.074 | **0.00218** |

국소 `k`가 고온에서 저온으로 가며 **약 4배 감소**합니다. 잔열 구간은 `k`가 가장
큰 고온부인데 전 구간 평균을 적용해 느리게 나왔습니다.

### 1.2 정정된 값 — 외삽 없는 실측

| 구간 | **실측** |
|---|---|
| 78.0 → 72 | **15 초** |
| **78.0 → 64** | **45 초** |
| 78.0 → 54 | **129 초** |

| 전환 | 기존 기준값 | **정정** |
|---|---|---|
| 80.9 → 72 | 46 초 | **약 20 초** |
| **80.9 → 64** | **96 초** | **약 50 초** |
| 80.9 → 54 | 177 초 | **약 135 초** |

### 1.3 영향 범위

- **`fan=1` 계측의 비교 기준선**이 96초가 아니라 **약 50초**입니다.
  96초로 두면 팬 효과가 실제보다 약 2배로 보입니다.
- `9508917` **커밋 메시지에 "about 96 s"가 포함**돼 있습니다. 커밋은 수정하지
  않고 이 노트로 정정합니다. 코드 동작에는 영향이 없습니다 —
  `MODE_TEMP_RESIDUAL_MARGIN = 4.0f`는 히스테리시스 1.5·오버슛 1.2·강도 간격 8에서
  나온 값이고 96초와 무관합니다.
- **팬 정책 도입의 정당성은 유지됩니다.** 50초도 "수 초"가 아니며, 강도 54에서는
  약 135초입니다.

### 1.4 유지되는 단서

`STM32_Reply_Progress_14` §1이 지적한 두 가지는 그대로 유효합니다.

- 기준값 조건: **무하중 · SLEEP · 팬 OFF** (ESP32 캡처 전 구간 ToF 265~283 mm)
- `fan=1` 실측은 **팬 효과와 착용 효과가 한 값에 섞입니다.** 50초와의 차이를
  "팬 덕분"으로만 읽으면 안 됩니다.

## 2. 문서 번호 충돌 정리

`#13`과 `#14`가 양측에서 각각 발행됐습니다.

| 문서 | 발행 | 대상 |
|---|---|---|
| `ESP32_Reply_Progress_13` | ESP32 | STM32 #12 |
| `STM32_Reply_Progress_13` | STM32 | ESP32 #11 |
| `ESP32_Reply_Progress_14` | ESP32 | STM32 #13 |
| `STM32_Reply_Progress_14` | STM32 | ESP32 #13 |

**재할당하지 않습니다.** 이미 상호 인용된 문서들이 깨집니다.
인용은 `STM32_Reply_Progress_13`처럼 **파일명 전체**로 합니다.

이 노트가 **#15**이며, 양측 공통 번호로 이어갑니다.

## 3. 교차 검증 — 담당 전환으로 처음 가능해진 확인

지금까지 문서 인용으로만 받아들였던 항목을 코드로 대조했습니다. **전부 일치합니다.**

| 확인 항목 | 근거 | 결과 |
|---|---|---|
| FORCE_ON이 FORCE_UP과 **같은 설정값**으로 조절 | `mode.c:1950` `i_Mode_Is_TempHeater_Over(..., f_Mode_Get_Temp_ForceUp())` | ✅ |
| 설정값 초과 시 **히터 OFF** (가열 아닌 냉각 방향) | 같은 위치 `v_Mode_Heater_Off()` | ✅ Q40 근거 확정 |
| 여유값 상수 4.0 | `mode.h:370` `MODE_TEMP_RESIDUAL_MARGIN 4.0f` | ✅ |
| on/off 문턱 분리 | `9508917` — `> f_set + MARGIN` / `<= f_set` | ✅ |
| FORCE_ON 종료 시 팬 해제 | `9508917` — `v_Mode_CoolFan_Disable()` | ✅ |
| 계측 로그 `settled`/`unsettled` 양쪽, `from=`·`fan=` 포함 | `b22319d` | ✅ |

**Q40(온도 하한 미도입) 판단이 이제 코드 근거를 갖습니다.** 이전에는 상대 인용만
보고 동의했던 사항입니다.

## 4. 미결 항목 — 전부 하드웨어 대기

| # | 항목 | 필요 조건 |
|---|---|---|
| 1 | Q23 실물 카드 회수·포맷 검증 | 벤치 + 사용자 조작 |
| 2 | 냉각 계측 `fan=1` | 1번 세션에 포함. **기준선 약 50초** |
| 3 | 장시간 SD 세션 | 벤치 장시간 점유 |
| 4 | 백필 동시 구간 계측 | 양측 + 벤치 |
| 5 | BLE 동시 접속 실측 (§9.5) | 장치 다수 |

### 벤치 세션 계획 (실행 전 사용자 확인 필요)

합의된 "카드 우선" 순서를 지킵니다.

1. **카드 회수 → 포맷 검증** (`validate_psa.py` / `verify_format.py` 활용)
2. **잔열 재진입 1회** — `[I/FORCE]ON settled|unsettled` 자동 기록
3. 캡처: ESP32 시리얼(`/dev/ttyUSB1`) + STM32 RTT 동시

**제약**:
- ST-Link/SWD 접속은 **사용자 승인 없이 하지 않습니다.** DAP 연결이 히터를
  구동하는 MCU를 리셋할 수 있습니다.
- 잔열 상태를 만들려고 `0x51`로 FORCE_* 를 강제하지 않습니다. 가열 사이클을
  임의로 명령하는 것이 됩니다.
