## 2. §4 STM32 무응답 — 펌웨어 적재 직후의 정상 동작입니다

**결함이 아닙니다.** 관측하신 조건이 정확히 이 상태와 일치합니다.

### 2.1 기전

펌웨어를 적재하면 마지막에 타깃이 리셋됩니다.

```
** Verified OK **
** Resetting Target **
```

**이 리셋은 콜드 부팅 경로로 들어가고, 그 경로의 도착지는 `modeOFF`입니다**
([main.c:355](../Core/Src/main.c:355) 주석의 "modeOFF cold-boot path").
`modeOFF`에서 `MODE_LOWPWR_ENTRY_DELAY`(1,000 ms) 뒤 STOP 모드로 진입합니다
([mode.c:2206](../User/Edit/src/mode.c:2206)).

**STOP에서는 CPU가 멈추므로 UART로 아무것도 나가지 않습니다.**
전원 버튼을 누르기 전까지 이 상태가 유지됩니다.

### 2.2 관측과 대조

| 그쪽 관측 | STOP 모드에서 |
|---|---|
| `0x43` 연속 타임아웃 14회 | ✅ 응답 없음 |
| STAT 0줄 | ✅ 송신 없음 |
| ESP32는 정상, 재부팅 안 함 | ✅ ESP32와 무관 |
| **발생 시점 = 적재 직후** | ✅ **적재가 이 상태를 만듭니다** |

네 가지가 모두 맞습니다. 특히 마지막이 결정적입니다 — 저희가 그날 여러 차례
적재했고, **적재할 때마다 전원 버튼을 누르기 전까지 이 창이 열립니다.**

### 2.3 새 코드 경로는 아닙니다 — 확인했습니다

`2aa197f`의 쓰기 실패 경로가 멈춤을 만들 수 있는지 따로 봤습니다.

`v_log_close_and_index()`의 `f_open` + 512 B 읽기는 `SD_TIMEOUT_*`로 상한이
있고(최대 600 ms), 지속 실패 시에는 그 앞에서 `b_SdMount = false`가 되어
`f_open`이 즉시 실패로 돌아옵니다. **70초 규모의 정지를 만들 경로가 없습니다.**

다만 RTT 캡처가 없어 **배제가 아니라 정합성 확인까지**입니다. 재현되면
캡처하겠습니다.

### 2.4 제안 — 그쪽에서 구분할 수 있습니다

이 창은 앞으로도 적재할 때마다 열립니다. **결함과 구분할 수단**이 있으면
좋겠습니다.

현재 `0x43` 무응답만으로는 "STOP 중"과 "고장"이 같아 보입니다. 저희 쪽에서
STOP 진입을 알릴 방법이 없습니다 — 알리는 순간 이미 CPU가 멈추기 때문입니다.

**ESP32 측에서 `evtBoot(0x81)` 수신 이력으로 구분 가능합니다.**

| 상황 | 직전 이력 |
|---|---|
| 적재 후 STOP | `0x81` 없이 조용해짐 |
| 실제 고장 | 세션 중 갑자기 끊김 |

필요하다고 보시면 검토해 주십시오. **저희 조치 요청은 아닙니다.**

## 3. §3 인덱스 독립 검증 — 저희 쪽 준비 완료

`boot=56` 로테이션을 기다리는 것에 동의합니다. `boot=54`가 전원 재투입으로
닫혔으므로 부팅 스캔과 구분되지 않는다는 지적도 맞습니다.

로테이션 시점에 저희 시리얼에 이 줄이 찍힙니다.

```
[I/SD_LOG]closed 00000038_0000.psa size=2880592 indexed=N
```

`0x38 = 56`입니다. 대조 항목은 셋입니다.

| # | 확인 |
|---|---|
| 1 | 재부팅 없이 `boot=56` file 0이 `0x45`에 나타나는가 |
| 2 | 같은 시점에 `closed ... indexed=N`이 찍히는가 |
| 3 | `indexed=N`과 `0x45` total이 같은가 |

**벤치에 `caecf97`이 적재돼 있고 이 로그가 포함**돼 있습니다. 결과 보내주시면
저희 캡처와 맞춰보겠습니다.

## 4. §2.3 — 공통점을 하나 덧붙입니다

> 세 번 다 **"맞는 숫자를 틀린 범위에 적용한"** 형태였습니다.

정확한 정리입니다. 한 가지 덧붙이면, **세 번 다 숫자를 낸 쪽과 그것을 근거로
쓴 쪽이 달랐습니다.**

| 건 | 숫자를 낸 쪽 | 그 위에 결론을 세운 쪽 |
|---|---|---|
| 계측 아티팩트 | ESP32 | STM32 (`_21` §1.4) |
| `txFail=0` | STM32 | STM32 (자기 것) |
| BLE 재시도 지목 | ESP32 | 양측 |

`txFail=0`만 저희가 낸 숫자를 저희가 쓴 경우인데, **그래서 더 오래 갔습니다.**
남의 숫자는 인용할 때 한 번 더 보게 되는데, 자기 숫자는 이미 검증했다고
여기기 때문입니다.

`flags` 비트0을 넣은 것도 저희이고 `txFail=0`을 근거로 쓴 것도 저희인데,
**그 필드가 어느 구간을 덮는지는 그쪽이 물어봐서 드러났습니다.**
