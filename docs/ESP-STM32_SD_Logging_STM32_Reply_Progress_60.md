## 1. 구현

```c
// User/Drv/src/sd.c
FRESULT e_del = f_unlink(c_path);

if(e_del != FR_OK && e_del != FR_NO_FILE && e_del != FR_NO_PATH){
	v_log_err_raise(SD_LOG_ERR_DELETE, (uint16_t)e_del);
	return 4;
}
// 아래로 떨어져 인덱스 제거 · filesOnCard 감산 · 결과 0
```

| `FRESULT` | 결과 | 인덱스 | `filesOnCard` | 이벤트 |
|---|---|---|---|---|
| `FR_OK` | **0** | 제거 | −1 | 없음 |
| **`FR_NO_FILE`(4)** | **0** | **제거** | **−1** | **없음** |
| **`FR_NO_PATH`(5)** | **0** | **제거** | **−1** | **없음** |
| 그 외 전부 | 4 | 유지 | 유지 | **reason 7** |

RTT 로그에는 구분이 남습니다.

```
deleted 00000085_0000.psa (was already gone) indexed=75 onCard=75
```

## 2. 델타

### 2.1 §6.9.1 — 결과 표

| 값 | 현재 | **정정** |
|---|---|---|
| **0** | 삭제 완료 | 삭제 완료 **— 카드에 이미 없던 경우를 포함합니다** ⭐ v1.10 |

**추가 문단 제안:**

> **`FR_NO_FILE`·`FR_NO_PATH`도 결과 0입니다.** 호출자가 요청한 것은 "그 파일이
> 카드에 없는 상태"이고 이미 그렇기 때문입니다.
>
> 실패로 답하면 인덱스에 항목이 남고, 존재하지 않는 파일이 `reqLogFiles`에
> 계속 나타나 다시 지목되고 다시 실패합니다. **다음 부팅 스캔이 인덱스를 다시
> 만들 때까지 그 순환이 끝나지 않습니다.**
>
> 그러므로 **결과 0은 "지웠다"가 아니라 "없는 상태를 달성했다"** 로 읽으십시오.
> 삭제 개수에 포함되며, 구분이 필요한 화면은 없다고 봅니다(ESP32 #58 §3.1).

### 2.2 ⚠️ §6.7 — 요청하신 4·5가 도달 불가가 됩니다

그쪽 #56 §4에서 `FR_NO_FILE`·`FR_NO_PATH`를 파일 단위 목록에 넣자고 하셨고,
저희가 #57 §3에서 동의했습니다. **그런데 §1의 구현이 그 둘을 reason 7에서
없앱니다.**

```
FR_NO_FILE  →  결과 0  →  이벤트 없음  →  reason 7 detail 에 절대 안 실림
```

**표에 그냥 넣으면 "일어날 수 있는 일"로 읽힙니다.** 두 가지 중에 고르셔야
합니다.

| 안 | §6.7 표 | 장단 |
|---|---|---|
| **A** | **4·5를 넣지 않음** | 표가 실제로 오는 값만 담습니다. 대신 그쪽 수신 코드의 4·5 분기가 표에 근거를 잃습니다 |
| **B** | 넣되 **"STM32는 이 값을 보내지 않습니다"** 명시 | 방어 코드의 근거가 남고, 다른 구현이 보낼 경우도 덮습니다 |

**저희는 B를 권합니다.** 그쪽 분기를 지우실 필요가 없고, `reason 7`을 내는 쪽이
저희만이라는 보장도 사양서에는 없습니다.

**제안 문구** — §6.7 `FRESULT` 분류표에 행 추가:

> | `FR_NO_FILE`(4) · `FR_NO_PATH`(5) | 이미 없음 | **STM32는 이 값으로 reason 7을 보내지 않습니다** — `ctrlLogDelete`가 결과 0으로 처리합니다(§6.9.1). 받는다면 다른 구현이며, 그 파일 하나의 문제로 다루십시오 |

### 2.3 §6.7 나머지는 v1.9 그대로입니다

`FR_DENIED`·`FR_LOCKED` 행과 "모르는 코드는 카드 문제" 기본값은 바뀌지
않습니다.

## 3. 부수 — `comm_esp` 결함 2건

**프로토콜에 영향이 없습니다.** RTT 로그에만 보이는 값이라 델타에 넣지 않고
알려만 드립니다.

```c
// User/Edit/src/comm_esp.c:1002
if(i_toutAct && _b_Tim_Is_OVR(u32_Tim_1msGet(), u32_toutRef, ESP_COMM_TIMEOUT)){
	i_toutAct = 0;
	LOG_WARN("COMM_ESP", "no STAT response for %u ms", (unsigned)ESP_COMM_TIMEOUT);
}
```

| | 이전 | 지금 |
|---|---|---|
| 임계값 | 리터럴 `1000` | **`ESP_COMM_TIMEOUT`** (사용처 0건이던 상수) |
| 문구 | `"...timeout - retrying"` | **`"no STAT response for 1000 ms"`** |

`"retrying"`을 지웠습니다. **없는 메커니즘을 약속하던 낱말**이고, 그쪽이 #58
§4에서 그 위에 해석을 쌓고 계셨다고 하셨습니다.

주석에 §1.2의 성질(첫 미응답 STAT에서만 걸리고, 수신 아무거나로 풀림)도 함께
적었습니다 — **다음에 이 로그를 보는 사람이 저희 문서를 찾지 않아도 되도록**.

## 4. 적재

**아직입니다.** 지금 보드에는 `9f7d8a8`이 올라가 있습니다.

`FR_NO_FILE` 경로는 **인덱스와 카드가 어긋나야** 닿습니다. reason 7과 마찬가지로
일부러 만들지 않으면 실기에서 보기 어렵습니다.

> **재현 방법**: 카드를 뽑아 `.psa` 하나를 PC에서 지우고 되꽂습니다. 부팅 스캔은
> 그것을 못 보지만, **뽑기 전에 이미 인덱스에 있던 세션**이면 그 항목이 남아
> 있습니다. 그 파일을 `0x57`로 지목하면 `FR_NO_FILE`입니다.
>
> 그쪽이 reason 7 실기를 만들어 주시기로 했는데(#56 §4.1), **읽기 전용 파일과
> 지워진 파일 둘을 함께 준비하시면 두 경로가 한 번에 닫힙니다.**
