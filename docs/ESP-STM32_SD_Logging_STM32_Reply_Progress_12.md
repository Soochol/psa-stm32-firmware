## 1. §2.4 조치 — 잔열 구간에 팬을 켭니다 (`9508917`)

### 1.1 변경 내용

FORCE_ON의 온도 조절부에 다음을 추가했습니다.

```c
float f_ir  = f_IR_Temp_Get();
float f_set = f_Mode_Get_Temp_ForceUp();
if(f_ir > (f_set + MODE_TEMP_RESIDUAL_MARGIN)){   // 4.0 °C
    v_Mode_CoolFan_Enable();
}
else if(f_ir <= f_set){
    v_Mode_CoolFan_Disable();
}
```

### 1.2 여유값 4 °C의 근거

보고 #10 §1.4에서 "채터링을 막을 여유값이 필요하고 그 값을 정하려면 실측이 있어야
한다"고 썼는데, **실측 없이 정할 수 있었습니다.** 이미 확정된 세 숫자 사이에
명확한 빈 구간이 있습니다.

| 값 | 출처 |
|---|---|
| 조절 히스테리시스 밴드 | `MODE_TEMP_HYSTERESIS_OFFSET` = **1.5** |
| 램프 오버슛 최대 | 실측 **1.2** (보고 #05 §5) |
| **여유값** | **4.0** |
| 강도 단계 최소 간격 (72→64) | **8** |

- 정상 조절은 설정값에서 최대 1.5까지만 벌어지므로 **4를 넘지 못합니다** → 팬 미동작
- 잔열은 최소 8 이상 벌어지므로 **반드시 4를 넘습니다** → 팬 동작

즉 두 상황이 계측 없이도 분리됩니다. 실측은 이제 **여유값을 정하기 위한 것이
아니라 효과를 확인하기 위한 것**이 됐습니다.

### 1.3 켜는 문턱과 끄는 문턱을 다르게 뒀습니다

| 동작 | 문턱 |
|---|---|
| 켜기 | `설정값 + 4.0` 초과 |
| 끄기 | `설정값` 이하 |

같은 값으로 판정하면 경계에서 켜졌다 꺼졌다 합니다. 4 °C 폭의 히스테리시스가
그것을 막습니다.

### 1.4 종료 시 해제 — 새는 경로를 함께 막았습니다

FORCE_ON 종료 시 `v_Mode_CoolFan_Disable()`을 호출합니다.

**이것이 없으면 저희가 없던 결함을 만들 뻔했습니다.** `v_Mode_Sleep()`은 쿨링팬을
건드리지 않습니다. FORCE_ON이 팬을 켠 채 타임아웃으로 SLEEP에 진입하면
**끄는 주체가 없어 계속 돕니다.**

변경 전에는 FORCE_ON이 팬을 켜지 않았으므로 이 경로가 존재하지 않았습니다.
켜는 코드만 넣고 끄는 코드를 넣지 않았다면 배터리 소모가 조용히 늘어났을 것입니다.

FORCE_DOWN은 필요하면 자기가 다시 켜므로 영향받지 않습니다.

## 2. 계측 로그 (`b22319d`)

### 2.1 두 경로를 모두 기록합니다

```
[I/FORCE]ON settled   from=80.9 ir=64.0 set=64.0 after 31200ms fan=1
[I/FORCE]ON unsettled from=80.9 ir=71.2 set=64.0 after 60000ms fan=0
```

**`unsettled`가 오히려 본체입니다.** FORCE_ON 타임아웃은 60초이고 그쪽 추정은
96초이므로, **정상적으로는 안착 전에 모드가 끝납니다.** `settled`만 기록했다면
바로 이 시나리오에서 로그가 한 줄도 나오지 않았을 것입니다.

`from=`을 넣은 이유는 진입 온도가 없으면 `after 60000ms`가 무엇을 뜻하는지
해석할 수 없기 때문입니다.

### 2.2 `fan=` 필드의 의미

`i_Mode_Is_CoolFan_Act()` 결과이며 **세 조건을 모두 반영**합니다.

```c
if(x_modeCoolfan.u16_on && x_modeCoolfan.u16_now){ return 1; }
```

| 조건 | 주체 |
|---|---|
| `u16_on` | STM32 모드 로직 |
| `u16_now` | ESP32 `0x15` (현재 10) |
| 서스펜드 아닐 것 | 배터리 감시 (§3) |

따라서 잔열 조건인데 `fan=0`이 찍히면 배터리 서스펜드이거나 `0x15` 미수신입니다.
**진단이 로그 한 줄로 됩니다.**

## 3. 🔴 신규 정보 — 배터리 저전압 시 팬이 강제 정지합니다

§1의 정책을 넣으면서 확인한 것으로, **전제에 해당하므로 공유합니다.**

배터리 저전압 경고 시 세 액추에이터가 한꺼번에 정지합니다.

```c
v_Mode_Heater_Enable_Suspend();
v_Mode_CoolFan_Enable_Suspend();
v_Mode_BlowFan_Enable_Suspend();
```

히터가 함께 멈추므로 **안전 방향은 유지**됩니다. 발열원이 사라집니다.

다만 §1의 팬 정책은 이 상태에서 무효가 됩니다.

| 배터리 | 잔열 냉각 |
|---|---|
| 정상 | 팬 가동 — 단축 |
| **저전압** | **팬 정지 — 자연 냉각(약 96초)으로 회귀** |

전원이 부족할 때 팬을 돌리는 것은 그 자체로 모순이므로 현재 동작이 맞다고 봅니다.
**§1 정책의 유효 범위가 "배터리 정상일 때"라는 점만 기록해 주십시오.**

그쪽에서 `ESP_WARN_BATTERY_LOW`를 수신하시면 이 상태에 들어간 것이며,
그 구간의 냉각 시간은 팬 정책 이전 값으로 돌아갑니다.

## 4. 실기 검증 — 미실시입니다

### 4.1 현재 상태

**코드는 반영됐고 실기 확인은 아직입니다.** 빌드는 통과했으며(플래시 증가 56 B),
동작 확인은 다음 세션에서 합니다.

### 4.2 `fan=0` 기준값을 저희가 재지 않았습니다

요청하신 "팬 조건 분리"에서 `fan=0` 쪽은 **저희 실측이 없습니다.**

`b22319d`(로그만, 팬 정책 없음)를 올려 한 번 재고 `9508917`로 교체하면 얻을 수
있으나, 세션 두 번이 필요합니다. 저희 판단으로는 **그쪽 96초 추정을 기준값으로
쓰는 것으로 충분**합니다 — 실기 데이터에 뉴턴 냉각을 피팅한 값이라 크게 틀리기
어렵습니다.

**다만 그쪽 추정으로 메울 수 없는 변수가 하나 있습니다.**

| 조건 | `capture_03` | 실사용 |
|---|---|---|
| 하중 | **무하중** (`D:270`) | **착용** |

착용 시 발열판이 신체에 접촉하며, 이는 열을 가져가는 동시에 단열도 합니다.
어느 쪽이 우세한지는 피팅으로 판단할 수 없습니다. **`fan=1` 실측이 나오면
이 변수까지 함께 반영된 값**이 됩니다.

기준값 비교가 꼭 필요하다고 보시면 알려주십시오. 세션을 나눠 진행하겠습니다.

### 4.3 카드 회수 세션에 포함합니다

전용 세션을 잡지 않습니다. 로그가 이미 빌드에 있으므로 **잔열 재진입을 한 번
수행하면 자동으로 기록**됩니다. Q23 실물 카드 회수 세션에 포함하겠습니다.

보고 #04에서 합의한 "카드 우선" 순서를 저희가 25분 세션으로 한 번 어겼으므로,
이번에는 지키겠습니다.
