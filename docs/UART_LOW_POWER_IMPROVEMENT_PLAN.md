# UART 절전 개선 계획 및 진행 상태

## 목표

추가 핀 없이 최초 배터리 연결 → 제품 OFF → 버튼 ON → OFF → 재ON 경로를
유지하고, 일시적인 OTA/LTE 조건 때문에 OFF 소비전류가 계속 높은 문제를 줄인다.
STM32와 ESP32의 기존 UART 프레임/토큰은 유지한다. 보드 업로드는 별도 진행한다.

## 구현 순서와 완료 조건

1. **OTA OFF 보류 — 구현 완료**
   - BUSY를 최종 실패로 보지 않고 STM32의 제한시간 내 재시도 유지.
   - ESP32가 OFF 의도를 보관하고 OTA/이미지 검증 종료 뒤 자동 실행.
   - OTA 소프트웨어 재시작 시 의도 보존, ON 시 취소, 전원 차단 시 초기화.
   - 보류/완료/취소 회귀 테스트 통과.
2. **모뎀 상태 확인 및 복구 — 구현 완료**
   - 기존 응답 정리 → CFUN=0 → CFUN? 실제 RF 상태 확인.
   - 명령별 5초 제한시간과 최대 30초 간격 재시도.
   - 모뎀 대기 중에도 STM32 UART를 처리하는 비동기 상태 머신.
   - 무응답, ERROR 후 회복, RF가 여전히 ON, 대기 중 ON 테스트 통과.
3. **최초 배터리 연결 경로 — 구현 완료**
   - STM32 초기 모드가 OFF이면 12V/녹색 LED 활성화와 SD 스캔 생략.
   - 버튼 ON 이후 정상 부팅 초기화는 유지.
   - 실제 전원 레일/LED 파형은 실보드 확인 필요.
4. **상태 표현·회귀 검증 — 소프트웨어 검증 완료**
   - UART wake pulse 단계를 이름 있는 enum으로 표현.
   - DMA busy/전송 큐 실패/지연 ACK/보류된 OFF 중 ON 테스트.
   - 두 펌웨어의 실제 절전 상태 머신을 연결한 호스트 wire-cycle 테스트.
   - STM32 release 및 ESP32 기본 타깃 빌드, diff 공백 검사.
5. **실보드 검증 — 미진행**
   - 두 이미지 적용 후 100회 ON/OFF, 짧은 누름/빠른 재ON, OTA 완료/취소.
   - UART 첫 바이트 손실, 모뎀 단절/복구, BLE/LTE·센서·로그 재개 확인.
   - 디버거 분리 상태의 배터리 전류 측정 및 실제 사용시간 재산정.

## 한계

호스트 검증은 전체 RTOS·부트로더·센서 초기화 또는 전기적 wake 타이밍을 대신하지
않는다. OTA가 끝나지 않거나 모뎀 RF 상태를 확인할 수 없으면 절전이 계속 지연될 수
있다. CFUN=0은 모뎀 전원 차단이 아니다. UART 절전 타임아웃을 이유로 STM32의
제품 종료 자체를 무한 대기시키지는 않는다.

세부 프로토콜과 검증 명령은 [UART_LOW_POWER.md](UART_LOW_POWER.md)를 참조한다.
